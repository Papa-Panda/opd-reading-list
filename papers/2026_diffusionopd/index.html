2一句话总结

扩散模型中的 OPD 统一视角

3核心命题

  • 多任务扩散模型 RL 难做：联合优化有跨任务干扰，级联 RL 易灾难遗忘
  • 先独立训练 task-specific teachers，再沿 student 自己的 rollout 轨迹把能力蒸馏进统一 student——解耦单任务探索与多任务整合。

4方法与机制

  • 把 OPD 从离散 token 提升到连续状态 Markov 过程
  • 推导闭式 per-step KL 目标（mean-matching 统一 SDE / ODE）
  • 解析梯度 vs PPO-style policy gradient 方差更低、泛化更好

5关键数字

  • 训练效率与最终性能全面超越 multi-reward RL 与 cascade RL 基线
  • 所评基准全部 SOTA

6在 OPD 主题中的位置

  • 把 OPD 从离散 token 提升到连续状态 Markov 过程：扩散模型的去噪轨迹是连续状态序列，token 级的 KL 目标需要重新推导。
  • 推导了闭式 per-step KL 目标（mean-matching 形式，统一 SDE / ODE 两种采样）；解析梯度相比 PPO-style policy gradient 方差更低、泛化更好。
  • 多任务设定：联合 RL 有跨任务干扰、级联 RL 易灾难遗忘；方案是先独立训练 task-specific teachers，再沿 student 自己的 rollout 轨迹把能力蒸馏进统一 student——解耦单任务探索与多任务整合。
  • 数字：训练效率与最终性能全面超越 multi-reward RL 与 cascade RL 基线；所评基准全部 SOTA。
  • 这是仓库里唯一一篇跳出 LLM token 世界的 OPD：连续控制 / 生成模型的 OPD 长什么样，看这篇。

7思考题

  1. 把 OPD 从离散 token 提升到连续状态 Markov 过程：KL 目标为什么能有闭式 per-step 形式？mean-matching 统一 SDE / ODE 的关键数学步骤是什么？
  2. 先训 task-specific teachers 再蒸馏进统一 student：这 genuine 地解决了跨任务干扰，还是把干扰推迟到了蒸馏阶段？student 的容量瓶颈会在哪里重新出现？
