2一句话总结

OPD 的典型陷阱、内在机制与系统性修复

3核心命题

  • 系统实证 OPD / OPSD 何时有效、何时失效：数学推理上 OPD 对 teacher 选择与 loss 形式高度敏感，结果好坏参半。

4方法与机制

  • 三个失败机制：(1) student 前缀导致的 teacher-student 分布失配 (2) 有偏 TopK reverse-KL 梯度的优化不稳定 (3) OPSD 中 PI-free 策略聚合 instance-specific 特权信息不足
  • 修复：stop-gradient TopK、RLVR-adapted teacher、SFT-stabilized student

5关键数字

  • OPSD 在 PI 为共享隐规则（如 system prompt / 对齐偏好）时有效
  • instance-specific PI 时失效

6在 OPD 主题中的位置

  • 与 revisiting-opd 同属「失败模式实证」：两份独立的 OPD 失效解剖，一个偏机制分类、一个偏 token 级实证，互为对照。
  • 三个失败机制：(1) student 前缀导致的 teacher-student 分布失配——teacher 在 student 自己走偏的前缀上给出的指导不可靠；(2) 有偏 TopK reverse-KL 梯度的优化不稳定；(3) OPSD 中 PI-free 策略聚合 instance-specific 特权信息不足。
  • 修复三件套：stop-gradient TopK、RLVR-adapted teacher、SFT-stabilized student——核心思想都是先把 student / teacher 拉回可信区域再蒸馏。
  • 关键边界发现：OPSD 在特权信息（PI）为共享隐规则（如 system prompt / 对齐偏好）时有效；PI 为 instance-specific（如单题的特权解法）时失效——给「什么知识可蒸馏」划了线。

7思考题

  1. student 前缀导致的分布失配：为什么 teacher 在 student 生成的前缀上给出的指导不可靠？这和语言模型的 exposure bias 是同一回事，还是 OPD 特有的新问题？
  2. OPSD 在 PI 为共享隐规则时有效、instance-specific 时失效——这对自蒸馏（self-distilled-reasoner 恰恰依赖 verified traces 这类 instance-specific 特权信息）意味着什么？两篇的结论冲突吗？
